1. ALGORITHME DE MATCHING
================================================================================

1.1 VUE D'ENSEMBLE DU PIPELINE
------------------------------

  rawSpan (string brut tapé par l'utilisateur)
      │
      ▼
  [0] BalanceParens       -- rééquilibre ( ) avant tout
      │
      ▼
  [1] Tokenizer.Tokenize  -- découpe en CanonicalToken[]
      │                        (Raw, Canonical, Name, Generic,
      │                         IsConnector, HadSpaceBefore, Start, End)
      ▼
  [2] Pour chaque PatternDef dans _repo.Patterns :
      │     PatternMatcher.TryMatch(pattern, tokens) -> MatchResult?
      │         - parse le DSL de pattern.Match
      │         - backtracking récursif, gère les slots, les littéraux,
      │           les alternatives, les optionnels, SPACE, skip connectors
      │     Si succès → TemplateRenderer.RenderAll(pattern.Template, mr)
      │                     - substitue {{slot}} par la valeur rendue
      │                     - pour EXPR/ATOM : récursion jusqu'à profondeur 3
      │                     - applique précédence (braces→powers→fractions)
      │                     - produit 1..3 variantes d'index consistant
      │     Candidates += LatexSuggestion[]  (avec score)
      ▼
  [3] Tri par score décroissant
      │
      ▼
  [4] Déduplication sur le LaTeX normalisé (sans whitespace)
      │
      ▼
  [5] Filtre : si plus d'un candidat, on drop tout ce qui est < 30% du top,
      SAUF les full-coverage (consumed == total) qu'on garde toujours
      │
      ▼
  IReadOnlyList<LatexSuggestion>  (triée, dédupliquée, seuillée)


1.2 ÉTAPE 1 — PRÉ-TRAITEMENT
----------------------------

  BalanceParens(span) — PatternEngine.cs:120
    - ')' en trop :  suppression L→R des fermetures qui feraient dépasser depth < 0
    - '(' en trop :  ajout de ')' à la fin jusqu'à ce que opens == closes
    But : permettre aux captures EXPR de ne pas être rejetées par ParensBalanced
    quand l'utilisateur oublie/ajoute une paren.

  Pré-traitement tokenizer :
    - s.Replace("\"", "''")  -- deux guillemets → double prime (seconde dérivée)


1.3 ÉTAPE 2 — TOKENISATION
--------------------------

  Tokenizer.Tokenize(span)  — Tokenizer.cs

  A) Split(span) :
     1. whitespace → séparateur (non conservé)
     2. digits  [+ '.' interne si entouré de digits]  → NUMBER piece
     3. lettres unicode consécutives  → mot alphabétique
     4. opérateurs multi-caractères connus (triés par longueur décroissante,
        greedy-match)  → une seule piece : "->", "<=", "==", ">=", etc.
     5. autres caractères non-espaces → token unitaire
     Chaque piece porte (start, end) absolus dans le span source.

  B) MergePhrases(pieces) :
     Fusionne les phrases stop déclarées dans _language.yaml :
       "for all"     → FORALL
       "pour tout"   → FORALL
       "quel que soit" → FORALL
       "il existe"   → EXISTS
       "there exists" → EXISTS
       "tel que"/"tels que"/"telle que" → SUCH_THAT
       "such that"   → SUCH_THAT
       "on a", "soit", "on pose"... → stop phrases absorbées (token CONNECTOR)
     Algorithme : match le plus long d'abord.

  C) Canonicalize(piece) — pour chaque piece produit un CanonicalToken :
     1. Phrase mergée ayant un mapping → token nommé
     2. Match exact sur alias (prioritaire) → TokenDef correspondant
        - Name = nom canonique majuscule (LIMIT, PROBA, REALS...)
        - Canonical = forme LaTeX ("\\lim", "P", "\\mathbb{R}"...)
        - IsConnector = true si role == "connector"
     3. Fallback lowercase si piece.length ≥ 3 et piece toute-lettres
        (permet "Lim"/"LIM" → LIMIT)
     4. Connector / stop word → CanonicalToken{ Generic="CONNECTOR", IsConnector=true }
     5. NUMBER literal (digits + '.'/',' internes) → Generic="NUMBER"
     6. Fuzzy match (Levenshtein ≤ fuzzy_max_distance, et d*2 ≤ min(|a|,|b|),
        piece.length ≥ 3) → match approximatif
     7. "un", "vn", "wn"... (2 lettres, suffixe n/N, préfixe uvwstUVWST)
        → IDENT mais Canonical = "u_n", "v_n", etc.
     8. Sinon → IDENT générique avec Canonical = Raw

  Propriétés posées sur chaque CanonicalToken :
     - HadSpaceBefore : true s'il y a au moins 1 whitespace avant ce token
     - Start / End     : offsets dans le span source


1.4 ÉTAPE 3 — MATCH DSL
-----------------------

  MatchDslParser.Parse(dsl) → List<MatchElement>

  Syntaxe :
    - TOKEN              → LiteralToken          (match par CanonicalToken.Name)
    - word               → LiteralWord           (match case-insensitive sur Raw)
    - SLOT:name          → Slot capturé (IDENT, EXPR, NUMBER, EXPR_LIST, ATOM,
                                          IDENT_SEQ, EQUATION_LIST,
                                          IDENT_UPPER_PAIR, VX_SHORT, CF_SHORT)
    - (A|B|C):name       → Alternative capturée
    - SPACE              → assertion "le token courant a HadSpaceBefore=true"
                           (zéro-width, consomme 0 token)
    - suffixe ?          → optionnel

  Distinction Upper vs lower dans le DSL :
    - Mot all-uppercase OU non-lettre → LiteralToken (match sur Name canonique)
    - Mot contenant une minuscule     → LiteralWord  (match sur Raw, case-insensitive)
    Ex : "u" dans "EXPR:a u EXPR:b" matche les raw "u" OU "U" (opérateur union).


1.5 ÉTAPE 4 — MOTEUR DE MATCHING
--------------------------------

  PatternMatcher.TryMatch(pattern, tokens)  — PatternMatcher.cs

  Backtracking récursif TryMatchRec(elems, e, tokens, t, slots, out finalT) :

  A) Avant chaque élément, on saute les CONNECTORS du flux de tokens
     tant que l'élément courant ne les demande pas explicitement.
     (Les stopwords et connectors sont silencieux.)

  B) Si tous les éléments sont consommés → match SUCCÈS (même s'il reste des
     tokens non consommés : match partiel autorisé, géré ensuite par le
     scoring/filter top-k).

  C) Par kind d'élément :

     SPACE  (zero-width)
       - Matche si HadSpaceBefore=true à la position courante
       - Si Optional : peut aussi skipper
       - Ne consomme AUCUN token

     LiteralToken / LiteralWord
       - CanMatchAtom(el, tokens[t]) avec t < tokens.Count
       - Si match → consomme 1 token et récurse
       - Si Optional → tente aussi de skip

     Alternative
       - Parcourt les alts. Match par Name canonique OU par Raw case-insensitive
       - Capture le token dans slot[CaptureName]
       - Si match → consomme 1 token et récurse

     Slot
       - TryMatchSlot(el, ...) selon SlotType (voir section 1.8)

  D) Greedy-first pour les optionnels : on tente TOUJOURS de CONSOMMER d'abord,
     puis de skipper seulement en dernier recours. Évite de laisser un
     LPAREN? non consommé alors que la paren est bien là.


1.6 ÉTAPE 5 — RENDU DU TEMPLATE
-------------------------------

  TemplateRenderer.RenderAll(template, match) → List<string>  — TemplateRenderer.cs

  Substitution :
    Regex \{\{\s*([A-Za-z_][A-Za-z0-9_]*)\s*\}\}  → pour chaque slot,
    rendu selon le SlotType :

      IDENT_SEQ   → raw privé du dernier char  ("un" → "u")
      VX_SHORT    → raw privé du premier char  ("Vx" → "x")
      CF_SHORT    → raw privé du premier char  ("Cf" → "f")
      IDENT       → Canonical (ou Raw si vide)
      NUMBER      → Canonical
      EQUATION_LIST → parts splittées sur ',' ou ';', joint par " \\\\ "
      EXPR / EXPR_LIST / ATOM :
          - Si le slot est contextuellement à l'intérieur de "{...}" LaTeX
            (ex. \frac{{{num}}}{{{denom}}}) et les tokens capturés commencent
            par '(' et finissent par ')' en même pair → on strippe les parens
            externes  ("(x+1)" → "x+1")
          - Sinon JoinTokens sur les tokens capturés (voir précédence plus bas)
          - RÉCURSION : si _recursionDepth > 0 ET |tokens| ≥ 2, on rappelle
            PatternEngine.Convert sur le sous-span correspondant, on prend
            les top-3 suggestions full-coverage comme alternatives.

  Profondeur max de récursion = 3 (MaxRecursionDepth dans PatternEngine.cs:31)
  → couvre "equation_simple → fraction_inline → sqrt_as_V" sans boucle infinie.

  Multi-variantes (INDEX CONSISTANT) :
    Pour chaque variante idx ∈ [0, max(slot.alts)] :
      remplace CHAQUE slot par son alt[idx] (ou top-1 si manque)
    → applique la même lecture à tous les slots
      ("tout en vecteur" OU "tout en littéral", pas de mix)
    Cap à 3 variantes max.

  Auto-wrap après _ ou ^ :
    Si un slot rend plus de 1 caractère et est précédé de '_' ou '^' hors braces,
    on wrap automatiquement avec {...} : x^abc → x^{abc}.

  JoinTokens — rendu avec précédence mathématique :
    Passe 1 : fonctions à braces (\sqrt, \vec, \tilde, \hat, \overline,
              \underline, \bar, \dot) + (...)  → \sqrt{inner}
    Passe 2 : puissances ^     (atom OP atom → atom^{exp})
    Passe 3 : subscripts _     (atom _ atom → atom_{idx} ; '_' étend sur chaînes
              additives : "O_n-1" → "O_{n-1}")
    Passe 4 : fractions /      (atom / atom → \frac{num}{denom})
    Chaque passe produit des tokens synthétiques (Generic=SYNTH) qui sont
    atomiques pour les passes suivantes.
    Fin : JoinFlat avec gestion d'espaces contextuels (macros ↔ alphanum).


1.7 ÉTAPE 6 — SCORING, DÉDUP, FILTRE
------------------------------------

  ComputeScore(pattern, matchResult, tokens) :
    consumed       = mr.ConsumedTokens (ou tokens.Count si 0)
    priorityFactor = pattern.Priority (ou 1 si 0)
    coverage       = consumed / tokens.Count
    slotBonus      = 1.0 + 0.2 * (canonicalCount / totalInSlots)
                     (bonus si les slots ont capturé des tokens nommés)
    score = coverage × consumed × priorityFactor × slotBonus

    Les variantes alt (i>0) ont score × 0.95 pour classer sans dominer.

  Déduplication normalisée : whitespaces supprimés avant comparaison
    ("V(x + 1)" et "V(x+1)" considérés identiques).

  Filtre top-k :
    Si plus d'un candidat, seuil = 0.3 × top.Score
    On garde tout ce qui est ≥ seuil
    + toujours garder les full-coverage (ConsumedTokens == TotalTokens)
      (ex. generic_expression qui est la fallback catch-all).


1.8 TYPES DE SLOTS
------------------

  SlotType         Description                                       Contraintes
  ─────────────────────────────────────────────────────────────────────────────
  IDENT            1 token non-connector                             t < count
  NUMBER           1 token avec Generic=="NUMBER"                    t < count
  IDENT_SEQ        1 token au format suite compacte (un, vn, wn, sn, tn)
  IDENT_UPPER_PAIR 1 token ≥ 2 lettres toutes majuscules (AB, XYZ)
  VX_SHORT         1 token "V" + 1 lettre minuscule (Vx, Vy, Vt)
  CF_SHORT         1 token "C" + ≥ 1 lettre minuscule (Cf, Cg, Ch)
  ATOM             1 atome : groupe parenthésé balancé OU token simple
                   non-opérateur, éventuellement suivi d'un appel de fonction
                   "f(args)" ; ET absorbe les suffixes d'ensembles math
                   (R*, R+, R-, R*+, R-{0}, R\{0})
  EXPR             séquence de 1..30 tokens avec parens balancées,
                   ne se termine pas sur un opérateur binaire isolé
  EXPR_LIST        = EXPR (alias sémantique, utilisé dans function_call)
  EQUATION_LIST    = EXPR mais DOIT contenir un ',' ou ';' interne
                   (pour splitter en plusieurs équations)

  Stratégie EXPR/ATOM :
    On parcourt les longueurs du plus court au plus long.
    - Premier match qui épuise l'input entier → on le prend immédiatement
      (plus courte EXPR qui consomme tout est gagnante).
    - Sinon on mémorise le meilleur match partiel (finalT le plus grand).

  FindAtomEnd :
    - '(' : jusqu'à la paren fermante balancée
    - '+'/'-' unaires : englobe l'atome suivant
    - identifiant suivi de '(' : englobe l'appel de fonction
    - ensemble math (R, N, Z, Q, C) : absorbe jusqu'à 2 suffixes (* + -)
      et optionnellement "-{...}", "\\{...}", "/{...}"


1.9 PRIORITÉS DE CHARGEMENT DES YAML
-------------------------------------

  Chaque fichier a une priorité ; à collision d'alias, la plus haute gagne.

    _core/core.yaml           → 0
    shared/symbolic.yaml      → 10
    {lang}/_language.yaml     → 50
    {lang}/algebra|analysis|… → 100

  La priorité per-pattern (champ "priority:") est optionnelle ; elle surcharge
  celle du fichier. Les valeurs effectives utilisées dans les YAML :

Ce fichier définit uniquement des TOKENS (pas de patterns), consommés ensuite

  Opérateurs arithmétiques :
    PLUS       +           aliases: +
    MINUS      -           aliases: -
    TIMES      \cdot       aliases: * .
    DIV        /           aliases: / :
    POWER      ^           aliases: ^ **
    UNDERSCORE _           aliases: _

    EQ         =           aliases: = ==
    NEQ        \neq        aliases: != <> =/=
    LT         <           aliases: <
    GT         >           aliases: >
    LEQ        \leq        aliases: <= =<
    GEQ        \geq        aliases: >= =>

    DOUBLEARROW  \iff        aliases: <=> <-> ⟺

2.2 shared/symbolic.yaml — PATTERNS LANGUAGE-AGNOSTIC (priorité 10)
===================================================================

  R-1  generic_expression                                              (prio 1)
       Fallback générique absorbant tout l'input.
       match:    EXPR:full
       template: {{full}}
       rôle : catch-all — garantit que les tokens en queue (ex. "+1" après
              "1/V(x)") ne sont jamais perdus.

  R-2  additive_expression                                             (prio 5)
       match:    EXPR:a PLUS EXPR:b
       template: {{a}} + {{b}}
       exemple : "AB(u v) + AC(d x)" → "AB(u v) + AC(d x)"

  R-3  subtractive_expression                                          (prio 5)
       match:    EXPR:a MINUS EXPR:b
       template: {{a}} - {{b}}
       exemple : "f(x) - g(x)" → "f(x) - g(x)"

  R-4  power_simple
       match:    ATOM:base POWER ATOM:exp
       template: {{base}}^{{exp}}
       exemples : "x^2" → "x^2"
                  "x**2" → "x^2"
                  "(x+1)^3" → "(x+1)^3"

  R-5  subscript_simple
       match:    IDENT:base UNDERSCORE EXPR:idx
       template: {{base}}_{{idx}}
       exemples : "u_n" → "u_n"     "x_0" → "x_0"

  R-6  fraction_inline
       match:    ATOM:num DIV ATOM:denom
       template: \frac{{{num}}}{{{denom}}}
       exemples : "1/2" → "\\frac{1}{2}"
                  "(x+1)/(x-1)" → "\\frac{x+1}{x-1}"

  R-7  function_call
       match:    IDENT:f LPAREN EXPR_LIST:args RPAREN
       template: {{f}}({{args}})
       exemples : "f(x)" → "f(x)"    "g(x,y)" → "g(x,y)"

  R-8  derivative_prime
       match:    IDENT:f PRIME LPAREN EXPR:x RPAREN
       template: {{f}}'({{x}})
       exemples : "f'(x)" → "f'(x)"   "g'(t)" → "g'(t)"

  R-9  named_function_cos       match: COS LPAREN? EXPR:arg RPAREN?
                                template: \cos({{arg}})
  R-10 named_function_sin       match: SIN LPAREN? EXPR:arg RPAREN?
                                template: \sin({{arg}})
  R-11 named_function_tan       (aliases tan, tg)
                                template: \tan({{arg}})
  R-12 named_function_ln        match: LN LPAREN? EXPR:arg RPAREN?
                                template: \ln({{arg}})
  R-13 named_function_log       (aliases log, lg)
                                template: \log({{arg}})
  R-14 named_function_exp       template: \exp({{arg}})
  R-15 named_function_arccos    (aliases arccos, acos)
                                template: \arccos({{arg}})
  R-16 named_function_arcsin    (aliases arcsin, asin)
                                template: \arcsin({{arg}})
  R-17 named_function_arctan    (aliases arctan, atan)
                                template: \arctan({{arg}})

  R-18 absolute_value
       match:    PIPE EXPR:x PIPE
       template: |{{x}}|
       exemples : "|x|" → "|x|"     "|x-1|" → "|x-1|"

  R-19 vector_norm
       match:    PIPE PIPE EXPR:u PIPE PIPE
       template: \|{{u}}\|
       exemple : "||u||" → "\\|u\\|"

  R-20 set_reals        REALS    → \mathbb{R}    aliases: R, IR
  R-21 set_naturals     NATURALS → \mathbb{N}    aliases: N, IN
  R-22 set_integers     INTEGERS → \mathbb{Z}    aliases: Z, IZ
  R-23 set_rationals    RATIONALS→ \mathbb{Q}    aliases: Q, IQ
  R-24 set_complex      COMPLEX  → \mathbb{C}    aliases: C, IC

  R-25 set_star         (prio 55)
       match: (REALS|NATURALS|INTEGERS|RATIONALS|COMPLEX):set TIMES
       template: {{set}}^*
       exemples : "R*" → "\\mathbb{R}^*"  "N*" → "\\mathbb{N}^*"

  R-26 set_plus         (prio 55)     match: <set> PLUS   template: {{set}}^+
       exemple : "R+" → "\\mathbb{R}^+"

  R-27 set_minus        (prio 55)     match: <set> MINUS  template: {{set}}^-
       exemple : "R-" → "\\mathbb{R}^-"

  R-28 set_strict_positive_a  (prio 60)
       match: <set> TIMES PLUS         template: {{set}}^{*+}
       exemple : "R*+" → "\\mathbb{R}^{*+}"
  R-29 set_strict_positive_b  (prio 60)
       match: <set> PLUS TIMES         template: {{set}}^{*+}
       exemple : "R+*" → "\\mathbb{R}^{*+}"
  R-30 set_strict_negative_a  (prio 60)
       match: <set> TIMES MINUS        template: {{set}}^{*-}
       exemple : "R*-" → "\\mathbb{R}^{*-}"
  R-31 set_strict_negative_b  (prio 60)
       match: <set> MINUS TIMES        template: {{set}}^{*-}
       exemple : "R-*" → "\\mathbb{R}^{*-}"

  R-32 set_minus_singleton_dash  (prio 65)
       match:    <set> MINUS LBRACE EXPR:val RBRACE
       template: {{set}} \setminus \{{{val}}\}
       exemples : "R-{0}" → "\\mathbb{R} \\setminus \\{0\\}"
                  "R-{-1}" → "\\mathbb{R} \\setminus \\{-1\\}"

  R-33 set_minus_singleton_slash (prio 65)
       match:    <set> DIV LBRACE EXPR:val RBRACE
       template: {{set}} \setminus \{{{val}}\}
       exemple : "R/{2}" → "\\mathbb{R} \\setminus \\{2\\}"

  Intervalles (match avec séparateur explicite, prio 50) :

  R-34 interval_closed_closed  LBRACKET EXPR:a (SEMICOLON|COMMA) EXPR:b RBRACKET
                               → [{{a}}, {{b}}]
                               ex: "[0;1]"→"[0, 1]", "[-2;5]"→"[-2, 5]"

  R-35 interval_closed_open    LBRACKET EXPR:a (SEMICOLON|COMMA) EXPR:b LBRACKET
                               → [{{a}}, {{b}}[
                               ex: "[0;+inf[" → "[0, +\\infty["

  R-36 interval_open_closed    RBRACKET EXPR:a (SEMICOLON|COMMA) EXPR:b RBRACKET
                               → ]{{a}}, {{b}}]
                               ex: "]-inf;5]" → "]-\\infty, 5]"

  R-37 interval_open_open      RBRACKET EXPR:a (SEMICOLON|COMMA) EXPR:b LBRACKET
                               → ]{{a}}, {{b}}[
                               ex: "]-inf;+inf[" → "]-\\infty, +\\infty["

  Intervalles avec séparateur = espace (prio 45) :

  R-38 interval_closed_closed_space  LBRACKET ATOM:a ATOM:b RBRACKET
                                     ex: "[0 1]" → "[0, 1]"
  R-39 interval_closed_open_space    LBRACKET ATOM:a ATOM:b LBRACKET

3.4 TESTS COMPOSITES
====================

Fichier : CompositePatternTests.cs

Règle : au moins un candidat doit contenir LES DEUX sous-chaînes part1 ET part2
(combinaisons inter-patterns fonctionnelles).

  input                              part1              part2
  ──────────────────────────────────────────────────────────────
  Sum k=1 to n sqrt(k)               \sum_{k=1}^{n}    \sqrt{k}
  int 0 to 1 x/sqrt(1+x^2) dx        \int_{0}^{1}      \sqrt{1+x^2}
  lim x->0 sin(x)/x                  \lim_{x \to 0}    \sin(x)
  lim n->+inf 1/sqrt(n)              \lim_{n \to +\infty}  \sqrt{n}
  (2x+1)/(sqrt(x)+1)                 \frac              \sqrt{x}

Limitation connue : les énoncés composés séparés par ':' ne sont pas encore
supportés (1 seul pattern par span pour l'instant).

3.6 TESTS DE COUVERTURE
=======================

Fichier : CoverageValidatorTests.cs

A) Gold_output_preserves_all_strong_input_tokens(lang, input, expected)
   Pour tout gold example (non-skip) en FR et EN :
     missing = CoverageValidator.FindMissingTokens(input, expected)
     Assert.Empty(missing)
   Protège contre les régressions où un pattern mangerait silencieusement un
   token "fort" de l'input (IDENT, NUMBER, token nommé à canonical non vide).

   Règles d'exclusion :
     - tokens ambigus : "VAR" (V peut devenir \forall, \sqrt, variance)
     - marqueurs structurels : "U" (→ \cup), "converge" (absorbé)
     - raccourcis : Vx, Cf (éclatés — seul le suffixe laisse trace)
     - opérateurs / délimiteurs / ponctuation : non tracés

B) Engine_output_preserves_input_on_typical_inputs
   Check runtime : on fait tourner l'engine réel et on vérifie la top
   suggestion.
   Inputs :
     "x+y=5"              "f(x)=2x+1"
     "Sum k=1 to n k^2"   "lim x->0 sin(x)/x"
     "V x ( R*"           "1/sqrt(x+1)"
     "AB+BC=AC"
